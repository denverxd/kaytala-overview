**The source is private** — the app handles real student records and ships to a single machine.
This page is an overview of what it does and the reasoning behind the parts that were hard.

## The problem

A teacher tracking several classes across two terms in spreadsheets. Rosters get retyped by hand
each term. Partial entry has nowhere safe to live, so a session of grading is either finished or
at risk. And there is no way to show one student their own marks during a consultation without
putting the rest of the class on screen in front of them.

Kaytala replaces the retyping and the exposure. It deliberately does **not** compute final
grades — the teacher's own sheet already does that, with a weighting that changes, so Kaytala
feeds that sheet rather than competing with it.

## What it does

- Imports rosters from two upstream formats, parsing names into components
- Dense grade-entry grid, keyboard-only
- Attendance one student at a time
- A large-type consultation view showing a single student only their own records
- Excel and PDF exports whose column layout is fixed by the sheet they feed

## Stack

Electron · React 19 · TypeScript · Tailwind 4 · SQLite (better-sqlite3) · TanStack Router ·
Vitest · GitHub Actions

## Constraints that shaped everything else

- **Offline-only.** No network at runtime, no CDN, no auto-updater. Fonts are bundled, and the
  content security policy is strict enough that a remote fetch fails loudly instead of falling
  back silently on a machine I cannot inspect.
- **Zero recurring cost.** Ships unsigned and is installed by hand.
- **One install, on Windows, developed on macOS.** Windows builds run only in CI, and a smoke
  test asserts the native module loaded and the data directory is writable — a green build is
  not evidence the app runs.

## Decisions worth explaining

**A score has three states, not two.** No record means not entered yet; an explicit "no score" is
distinct from a zero; and a real 0 is a number. Stored as absent row, NULL, and value. Code that
collapses NULL into 0 silently destroys a distinction the user specifically asked for, so it is
tested directly rather than left to convention.

**Attendance is derived, never stored.** Its score is the count of present marks, read at display
time, because the denominator is the number of sessions held and changes whenever one is added. A
cached count was rejected on how it fails, not on cost: a missed read shows a blank, but a missed
write shows a stale number that looks perfectly correct.

**Grades are never colour-coded, and absences never render red.** A student reads that screen
during a consultation. An absence is a fact, not an error state, and a wall of red and green turns
a working sheet into a verdict.

**Autosave everywhere, no Save buttons — paired with undo.** Forgetting to save once and losing an
hour of entry permanently destroys trust in the tool. But autosave also removes the "discard
changes" escape hatch, so it only ships alongside undo that covers the session.

**Entry never requires the mouse.** The grid is a single tab stop with roving focus. Enter moves
down, as in a spreadsheet, rather than entering and leaving an edit mode as the ARIA grid pattern
prescribes — the user comes from Excel, and an established habit outranks a guideline.

**The theme deletes its framework's default palette rather than overriding it**, so an off-palette
utility class fails to compile instead of quietly shipping. Contrast is held to 4.5:1 for text and
3:1 for focus rings and borders in both light and dark themes; a warm low-saturation palette is
exactly where that fails quietly.

## How it is built

- Decision records for anything that had a real rejected alternative
- Pure logic imports nothing from Electron, which is what makes it verifiable from macOS
- Append-only migrations; any migration that could lose data snapshots first, in the runner
  rather than by the author remembering
- 300+ unit and data-layer tests, with expected values written by hand rather than generated by
  the code under test
- Errors the user sees say what to do, never what broke — there are no developer tools on that
  machine and nobody to ask

## Status

In active development, roughly half the planned scope built. Not yet released.
